В L2 замени обещание следующего урока; в L5 покажи защиту без добровольных картинок. Согласуй D05/D06 и SYSTEM_INVARIANTS с типами полей; сохраняй историю старых решений с датой замены. ### 2. Перенеси поля и пройди оба интерфейса

| Поле | Урок и режим | Завершение и сайт |
|---|---|---|
| avatar | L3 strict, 3–6 версий; формула Subject/Style/Framing/Lighting; при новой версии изменяется ≥1 часть; на каждую принятую версию pros и cons по ≥3 слова; разные best/worst с причинами | Обязательно; лучший вариант 256×256 transparent PNG, существующие alt и частицы. Worst может быть менее подходящим без явной ошибки. |
| hobby-image-1…3 | L3 rapid, каждая из трёх независима, 1–6 попыток при участии; можно принять первую или любую допустимую из истории; следующая требует изменённую часть формулы и причину ≥3 слова | Добровольно; 640×480 JPG, alt из соответствующего hobby-title-N, привязка к тому же хобби L2. |
| theme | L4, первая карточка; RCTF, два варианта, mood в Format, выбор и принятая comparative/design justification. Сохранить текущие проверки, в т.ч. мягкую подсказку о похожем результате | Обязательно; шесть прежних пресетов и их палитры. |
| background | L4 rapid, вторая карточка, 1–6 попыток при участии; задание предлагает использовать выбранную палитру. Порядок на экране без серверного запрета до выбора темы | Добровольно; 1600×900 JPG, декоративный alt пустой, без людей, текста и водяных знаков. |

Сохрани ID, поменяй lesson-3/4.json и slots-config.json. Перенеси правила rapid, changeReasonMinWords, лимиты и соответствующие hints в оба конфига. Согласуй поиск банка по ID/самому длинному префиксу в validate.js и UI. Проверь app.js (groupsFor, правила, completion, редактор, история, пример prompt) и workspace-ui.js (цели, language, glossary, карточки требований). Не прячь незавершённые бонусы при завершении ядра; переключение уроков через существующие вкладки. Выполнение обязательного поля даёт готовность; разблокирует следующий урок учитель. В teacher.js и серверной сводке отдельно показывай готовность ядра и завершённые бонусы, по ученику — журнал обоих режимов. Проверь подсказки AI и mock по ID, размер, прозрачность, alt, UI сохранения ввода после отказа.

### 3. Сборка, поздний бонус, публикация

В runExport включай только принятое значение добровольного поля; открытый черновик с версиями равнозначен отсутствующей иллюстрации для сборки. Отсутствующий обязательный аватар или файл принятой картинки — диагностируемая ошибка. Пройди всю цепочку server → tools/site-builder.js → tools/fill-slots.js → index.html/styles.css → открытый экспорт. Для отсутствующей hobby-image скрыть только область изображения, текст карточки, навигацию и порядок сохранить. Для отсутствующего background показать цвет/градиент текущего пресета. Осмотри все пустые слоты, в т.ч. необязательный footer; в ученическом HTML нет надписей [ slot: … ], пустых src и битых ресурсов. Проверь demo-export.json, dev-preview.js, частицы и carousel с 0/1/3 картинками.

До выдачи семейной ссылки черновик бонуса можно открыть, генерировать и менять без отзыва готового preview или ранее пройденного аудита. Когда принято новое видимое содержание, прежняя сборка устаревает, аудит снимается, учитель пересобирает и проверяет перед выдачей. В текущем маршрутизаторе сравниваются все fields до/после: замени этот слишком широкий критерий на изменение публикуемого содержания для затронутых действий. Сохрани прежние защиты коррекций и приватного preview.

После публикации прямой старт/продолжение бонуса блокируется и в UI, и на сервере. Существующий grant допускает только done: расширь **точечно** для ещё пустого или начатого бонуса. Учитель открывает именно это поле; черновые попытки сохраняют действующий снимок, принятие с причиной расходует разрешение, записывает историю, отзывает старые preview/семейную ссылку и аудит. Дальше повторный аудит/выдача учителем. Состояние «ссылка уже выдавалась» сохранять и после отзыва, иначе исчезновение published само разблокирует все бонусы; не закрывать аудит/рефлексии, нужные для повторной выдачи. Проверь вход из student/teacher UI, GET старого токена и запрет постороннему классу.

### 4. Прочитай прежние состояния

Завершённый старый фон показывать в L4 с выбранным изображением, всеми prompt/pros/cons/best/worst и причинами; при отсутствии version брать прежний порядок. Для незавершённого strict-фона преобразовать представление в продолжаемый rapid: сохранить пути и историю, высчитать число использованных попыток, предложить принять существующую картинку или продолжить в остатке лимита. При шести — выбор из истории. Если L4 ещё закрыт, явно показать куда переехала работа; открыть по обычному учительскому маршруту. Для прежних хобби такой же доступ через L3. Проверить пересчёт готовности, edit grants и уже открытые уроки. Преобразование повторяемо, подтверждённая семейная версия остаётся доступной до реального изменения. Никакого массового пересева. Изменение формата описать в CONTRACT.

### 5. Что должен воспроизвести принимающий

1. Чистый ученик L2 → три разных аватара с оценками → best/worst → L3 готов → учитель открывает L4 → две темы и обоснование → Build проходит с нулём бонусов. Отрицательные примеры: два аватара, пустая причина, невалидный prompt, одна тема, выбор без обоснования. Баллы не участвуют.

Сравнить содержимое/изображения контрольной сборки и отсутствие потерь; фиксировать допустимые изменения разметки.
