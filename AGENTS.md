# Работа с AI English Course

Вход: SESSION.md → tasks/00-BACKLOG.md → docs/SYSTEM_INVARIANTS.md. Затем docs/CONTEXT_MAP.md выбирает минимальный дополнительный контекст.

Приоритет: запрос владельца; утверждённое решение curriculum/DECISIONS.md и Lesson Spec; форматы docs/CONTRACT.md. Код и исполняемые тесты описывают фактическое поведение. Конфликт фиксировать, не исправлять молча по самому новому файлу. Исторические документы в docs/history и SESSION_HISTORY_ARCHIVE не являются задачами.

Перед изменением оценить конфиг, валидатор, сервер, UI ученика, UI учителя, экспорт, сохранённые данные, тесты и эксплуатацию. Для незатронутого слоя достаточно короткого объяснения. При конфликте с запросом предложить согласованное изменение всех затронутых частей; уже выданное разрешение не запрашивать повторно.

Одна задача — проверяемая ветка/PR. npm run check и npm test; для изменения пользовательского пути — браузерная проверка. PASS/FAIL/BLOCKED/NOT_RUN записывать честно. Небольшая правка оформления не требует всего research. Новое методическое утверждение — искать основание через SOURCES; параметры пилота не выдавать за научные нормативы.

Проверки используют отдельный DATA_DIR с fixtures. Не сбрасывать пользовательские профили, не останавливать чужие процессы Node. Временный тестовый сервер принадлежит тесту и останавливается им. После правки сообщать фактические проверки и статус процесса, без обязательного выдуманного «4/4».

Живые данные, .env, токены, резервные копии и runtime-сборки не входят в Git. Перед commit проверить staged-набор. Перед merge требуется независимая приёмка PR; до неё PR остаётся draft. Не делать force push в main. SESSION держать короче 100 строк.
