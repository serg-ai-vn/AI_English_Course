# AGENTS.md — Протокол работы ИИ-агента над проектом AI English Course

## 1. Главный принцип: «Экономия контекста + Защита педагогических инвариантов»

Этот репозиторий организован так, чтобы любой ИИ-агент (OpenCode, Cursor, Claude Code, Codex) мог вести разработку, **не забивая контекстное окно** десятками тысяч строк архивной документации, но при этом **на 100% соблюдал методологию уроков и межфайловые контракты платформы**.

**Жёсткие правила чтения контекста при старте сессии:**
1. **Прочитай при старте обязательный базовый контур (3 компактных файла):**
   - `SESSION.md` (точка входа: текущее состояние, активная задача, последние шаги).
   - `tasks/00-BACKLOG.md` (таблица задач со статусами `TODO` / `IN_PROGRESS` / `DONE`).
   - `docs/SYSTEM_INVARIANTS.md` (**паспорт неприкосновенных правил уроков L1–L5, контракта для OpenAI и матрицы из 6 связанных слоёв кода**).
2. **При выполнении технической задачи из очереди `tasks/`:**
   - Возьми ровно **ОДНУ** активную задачу (например, `tasks/TASK-01-critical-bugs-and-security.md`) и открой те исходные файлы кода, которые перечислены в секции `Файлы для чтения и изменения`.
3. **При любых вопросах пользователя по урокам или просьбах изменить механику урока / промпты / гейтинг / UI:**
   - **ОБЯЗАТЕЛЬНО** прочитай `docs/SYSTEM_INVARIANTS.md` и соответствующий план урока в `curriculum/Lesson_N.md` (`Lesson_1.md` .. `Lesson_5.md`, а при необходимости `curriculum/1_course_guide_teacher.md`).
   - Выполни **Протокол «Сначала предупреди — потом меняй» (`Impact Check Protocol`)** из раздела 5 файла `docs/SYSTEM_INVARIANTS.md`: проверь, какие из 6 слоёв кода (`config/lesson-N.json`, `validate.js`, `server.js`, `public/app.js`, `public/teacher.js`, `index.html` + `fill-slots.js`) затронет правка, и если изменение может нарушить смежный гейт или отображение — **сразу предупреди Сергея** и предложи безопасный вариант реализации до внесения правок.
4. **НЕ ЧИТАЙ** без прямого запроса пользователя архивный лог `docs/SESSION_HISTORY_ARCHIVE.md` (45 КБ) и внешние папки исследования рынка.

## 3. Протокол выполнения задач и работы с Git

1. **Одна задача = один атомарный коммит (или ветка):**
   - Перед началом работы над задачей убедись, что `git status` чистый.
   - Выполняй строго то, что описано в файле `tasks/TASK-XX-...md`. Не делай попутный рефакторинг файлов, которые не относятся к задаче.
   - Если в ходе работы меняется правило урока, синхронно обнови код (`config`, `validate`, `server`, `app`) и документацию (`docs/SYSTEM_INVARIANTS.md` + `curriculum/Lesson_N.md`).
   - После выполнения всех проверок из секции `Критерии приёмки (Acceptance Criteria)` обнови статус задачи в `tasks/00-BACKLOG.md` и сделай краткую запись в `SESSION.md`.
   - Сделай понятный коммит: `git add -A && git commit -m "fix(task-01): fix L2 export, motion syntax, L3 gate and preview security"`.
2. **Локальный сервер платформы (обязательная проверка после правок):**
   - Сервер запускается командой `node platform/server.js` (по умолчанию `http://localhost:3000`).
   - Никогда не останавливай `node platform/server.js` «для уборки» в конце задачи — Сергей тестирует платформу в браузере параллельно.
   - После любой правки в `platform/` или `tools/` перезапусти сервер и проверь 4 базовых маршрута:
     1. `POST http://localhost:3000/api/login` с телом `{"classCode":"DEMO","pin":"0000","role":"teacher"}` -> `200 OK`
     2. `GET http://localhost:3000/workspace.html` -> `200 OK`
     3. `GET http://localhost:3000/platform.css` -> `200 OK`
     4. `GET http://localhost:3000/app.js` -> `200 OK`
   - В конце ответа пользователю всегда явно пиши статус сервера (запущен / проверен, 4/4 эндпоинта `200 OK`).
3. **Бережное отношение к тестовым данным пользователя:**
   - **Профили для ручного тестирования (`Ziggy`, `Neo`, `Khoa`, `Nia`, `Rex` в `platform/data/progress/*.json`) всегда держи чистыми** (`lesson: 2, fields: {}, complete: false, unlockedLessons: [2]`) — Сергей тестирует гейтинг сам, шаг за шагом, с нуля. Профиль `Lumi` (`lumi.json`) оставлен заполненным (уроки 2–4 закрыты) как демо-образец для проверки консоли учителя и кнопки `Build site`.
   - **Никогда не вызывай `/api/reset` или `/api/reset-all` без прямого указания Сергея** (даже после своих smoke-тестов через curl). Если нужно проверить флоу на чистых данных — спроси Сергея или используй временный тестовый токен/профиль, не затирая прогресс Сергея.
   - Никогда не коммить в Git реальные API-ключи (`.env`) и временные файлы сессий (`platform/data/sessions.json`).
