### Ветки, данные, приёмка

1. Прочитай AGENTS → SESSION → BACKLOG → SYSTEM_INVARIANTS → CONTEXT_MAP. Сверь HEAD с origin/main и пакетом задания. Используй ветку feat/l3-l4-course для TASK-10. Первый draft PR направь в main. После проверенного коммита TASK-10 создай feat/course-step-points, второй draft PR направь в первую ветку. В описаниях укажи зависимость и SHA.
2. На отдельном порту подними общую версию из второй ветки в выделенном DATA_DIR: чистый синтетический ученик для полного маршрута и копия тестовых профилей для совместимости. Не направлять seed, reset или restore в Main/platform/data либо соседнюю LocalPreviewData. У владельца должен остаться его текущий просмотр. Дай адрес, способ входа в ученика и учителя, версию и сценарий проверки; секреты вне Git.
3. Владелец проходит маршрут: заголовок L2 → +очки → аватар → пропуск бонуса → выбор темы → сборка → поздний бонус → пересборка и аудит → публикация → разрешённое исправление. Отдельно показать одинаковую награду за два варианта работы с иллюстрацией, групповое начисление, отзыв и изменение цели через конфиг.
4. Для каждого PR зафиксируй PASS/FAIL/BLOCKED/NOT_RUN, команды, SHA, браузер/размер, синтетические данные, доказательства и ограничения. Только после проверки общей версии владельцем и независимой приёмки точного SHA первого PR — merge первого. Перенаправь второй PR в main, проверь diff, CI и независимую приёмку финального SHA второго. При смене поведения повтори пользовательский сценарий. Не сливай автоматически по зелёному CI.
5. Откат до merge — остановить только свой просмотр. После выпуска — откатить код по PR в обратном порядке; до запуска старого кода проверить чтение копии данных. Резервную копию восстанавливать в отдельный каталог, проверить журналы и ссылки, согласовать переключение. Выключение баллов через конфиг доступно независимо от отката уроков.

### Что собрать на репетиции

Учитель фиксирует для каждого псевдонима минуты на обязательную и дополнительную части, помощь и число попыток, пример самостоятельного объяснения, число завершивших аватар за 22 минуты и тему за 25, число успевших хотя бы одну иллюстрацию/фон. Отметить задержки и расход реальной генерации отдельно от mock, время учителя на баллы, понятность шкалы, разницу между быстрыми и медленными учениками. Сравнить по рубрике два объяснения «оставил» и «изменил». Вопросы пилота: укладываются ли дети в 90 минут, понимают ли право пропустить бонус, не начали ли менять удачную работу ради награды? Записать наблюдаемое и решение о следующей редакции.
