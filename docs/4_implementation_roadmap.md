## Порядок: сначала весь курс дословно, потом платформа

Контент — техзадание для платформы. Пока не зафиксирован текст всех 5 занятий, структура платформы — угадывание. Дешевле переделать абзац, чем переделать код.

**Как писать курс**: занятие за занятием, прямо в диалоге со мной. Заполняешь поля шаблона ниже (можно неполно, "как чувствуешь") → я предлагаю черновик → ты помечаешь, что оставляем/меняем → фиксируем версию → следующее занятие.

**Источник лексики для калибровки уровня**: официальные списки Cambridge (A2 Flyers ~500 слов, B1 Preliminary — следующая ступень) — cambridgeenglish.org/Images/506166-starters-movers-flyers-word-list-2025.pdf. Бери оттуда базу под тему занятия, не изобретай уровень на глаз.

## ФАЗА 2 — Платформа (после того как все 5 Lesson Spec Sheets зафиксированы)

Как только Фаза 1 закрыта, разделы 2, 6, 7 каждого занятия автоматически становятся исходником для конфига — не нужно ничего придумывать заново, только перенести в структурированный формат (JSON/YAML).

### ⬜ Шаг 1. Извлечь конфиг из 5 Lesson Spec Sheets
Один файл-конфиг на занятие: список лексики, правила гейтинга + тексты подсказок, список нужных слотов шаблона.

### ⬜ Шаг 2. HTML-шаблон со слотами
Собирается под слоты, которые реально всплыли из контента (раздел 8 каждого занятия) — не раньше, иначе слоты придётся угадывать.

### ⬜ Шаг 3. Движок валидации (гейтинг)
Один универсальный код, который читает правила из конфига любого занятия — не пишется отдельно под каждое занятие.

### ⬜ Шаг 4. Рабочее место ученика
Обёртка над шагами 2+3.

### ⬜ Шаг 5. Консоль учителя
Простая таблица — последние промпты по каждому ученику.

### ⬜ Шаг 6. Авторизация
Код класса + имя + PIN. Делается последним, самое простое.

## Почему это даёт модульность, которую ты хочешь

Гейтинг-движок и шаблон не знают заранее, что именно в занятии 3, а что в занятии 4 — они просто читают конфиг конкретного занятия. Значит, если через месяц захочешь поменять список слов в занятии 2 или добавить ещё одно правило гейтинга в занятие 4 — правишь один конфиг-файл, движок и весь остальной код не трогаешь вообще. Это и есть независимость блоков, только достигается она не архитектурным трюком в коде, а тем, что контент дописан первым и до конца — код изначально пишется как читатель данных, а не как контейнер для конкретных занятий.
