# План: сайт ученика → платформа

> **Точка входа в проект - `SESSION.md`** (состояние, следующий шаг, история). Этот файл - детальный трекер этапов.
> Статусы: `[x]` готово, `[/]` в работе, `[ ]` впереди.
> Правило: результат каждого этапа - это то, что можно открыть и пощупать руками, а не код ради кода.

## Цель

Через ~2 месяца от старта: платформа, оттестированная на первой живой группе, с которой можно идти в английские центры и предлагать бесплатную демо-группу на 5 занятий.

## Текущая точка (06.08.2026, вечер)

**Этап E закрыт полностью (куски 1-5): платформа + все 5 занятий.** Логин (код класса+имя+PIN, роли), рабочее место ученика (L2 текст → L3 визуал → L4 хобби-картинки + тема → L5 аудит + рефлексия), движок гейтинга `validate.js`, mock-LLM/картинки, консоль учителя (статусы, журнал по урокам, Unlock, Build site / Publish), экспорт single-file HTML + download для семьи. Аудит 06.08: спека ↔ платформа сверены, расхождения закрыты; `PLATFORM.md` — описание платформы как есть; `Lesson_4.md`/`Lesson_5.md` — v2 под реальность. L5 E2E на временном ученике (создан/удалён): все гейты + публикация 626 KB.

Дальше: планшетный тест (Этап D, ждёт железо) → L1 в платформе (загрузка фото в консоль) → перенос на сервер для живой группы.

## Этап B. Репетиция端到端 `[x]` (закрыта 27.07 - галерея из 7 сайтов одобрена)

Зачем: увидеть всю цепочку целиком до строительства платформы и докрутить шаблон по живому впечатлению, а не вслепую.

Схема:
1. **Ты** создаёшь 3 документа-заготовки — как будто результаты ученика после занятий 2, 3, 4 (форматы — в приложении ниже).
2. **Я** собираю из них контент-конфиг → прогоняю `export-site.ps1` → отдаю готовый `dist/<имя>.html`.
3. **Ты** открываешь сайт "глазами семьи" и говоришь, что докрутить. Правка → повторный экспорт занимает секунды.

Совет: сделай **двух разных "учеников"** (разные тексты, картинки, настроения). На паре сайтов сразу видно, где реальная уникальность, а где всё одинаковое — это и есть главный вопрос пилота.

Куда класть документы: `Kimi K3/rehearsal/` (создай папку, имена файлов — как в приложении).

- Проверка: экспорт по контракту воспроизводит одобренный `dist/ziggy.html` побайтово (MD5 совпал).
- Зафиксирован нюанс: luminance в particle-JSON 0-255, `particles.js` делит на 100 (насыщение >100 - одобренный вид, не нормализовать).
- Это точка стыковки с платформой: backend делает ровно то, что на репетиции делал агент руками.

**Осталось по платформе:** L1 (загрузка фото в консоль учителя — триггер Unlock L2), перенос на сервер для живой группы (код и контент не трогаем, меняется только слой хранения), планшетный тест (Этап D).

Сайт и платформа стыкуются через Этап C: рабочее место ученика наполняет те же слоты, экспорт — тот же `export-site.ps1`. Перенос на сервер (для живой группы) - отдельный шаг после локального одобрения, код и контент не трогаем, меняется только слой хранения.

## Приложение: форматы документов для репетиции

### 1. `rehearsal-L2-texts.md` (Занятие 2 — тексты)

```markdown
Ученик (псевдоним): 
Заголовок сайта (site-title): 
Подзаголовок (hero-subtitle): 
Текст "About Me" (1 абзац): 

Хобби 1 — название: 
Хобби 1 — текст (1-2 предложения): 
Хобби 2 — название: 
Хобби 2 — текст: 
Хобби 3 — название: 
Хобби 3 — текст: 

Текст футера (или оставь пустым — будет стандартный): 
```

### 2. `rehearsal-L3-visuals.md` (Занятие 3 — визуал)

```markdown
Аватар: <имя файла в rehearsal/ ИЛИ описание — подберу стендовую картинку>
Фон героя: <файл или описание>
Картинка хобби 1: <файл или описание>
Картинка хобби 2: <файл или описание>
Картинка хобби 3: <файл или описание>

(Опционально, пригодится для платформы: промпты, которыми "ученик" это генерировал)
```

### 3. `rehearsal-L4-theme.md` (Занятие 4 — тема)

```markdown
Описание настроения по-английски (как написал бы ученик): 
Второй вариант, с которым сравнивал (опционально): 
```

Маппинг настроения → пресет делаю по таблице mood words из `16_source_theme_presets.md` — заодно проверим логику, которая потом уйдёт в бэкенд.
