# Подготовка и загрузка очищенного проекта

Цель: https://github.com/serg-ai-vn/AI_English_Course . Владелец 29.10.2026 разрешил оставить репозиторий публичным и загрузить очищенный проект. Перед push повторно проверить видимость/ветки и staged-набор. Main не перезаписывать.

1. Сохранить исходный снимок вне Git; исходный baseline имеет известные дефекты, это не рабочий релиз. Санитарная подготовка до первого коммита разрешена и обязательна.
2. Проверить .gitignore: runtime platform/data, generated, dist, .env.* и backup исключены; fixtures — только синтетические демонстрации. Реальные токены/ключи не публиковать. sessions.json не удалять с диска ради Git. Если уже отслеживается: git rm --cached -- platform/data/sessions.json. Если ещё не отслеживается, достаточно ignore.
3. Прочитать npm scripts, выполнить npm ci, npm run build, npm run check, npm test. Просмотреть staged diff и список файлов после git add; статус до staging не заменяет эту проверку.
4. Для пустого remote создать минимальную main с описанием проекта, импорт/исправления загрузить отдельной веткой и draft PR. Для непустого remote работать от его main и сверить содержимое; не делать force push.
5. Независимый проверяющий повторяет тесты из свежего clone, проверяет данные/ключи и изменения педагогики. До приёмки PR остаётся draft, merge не выполнять.
6. Только после приёмки merge и точный тег проверенного состояния; push конкретного тега, не всех локальных tags. Live/Docker/пилотные NOT_RUN не объявлять завершёнными.

Откат: см. DEPLOY_RUNBOOK. Переключение Git-тега не возвращает JSON/изображения. Публичный source-репозиторий не означает публичный доступ к данным учеников; pilot использует собственный DATA_DIR и новые доступы.
