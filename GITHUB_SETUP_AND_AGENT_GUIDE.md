# Работа с GitHub после первой загрузки

Репозиторий: https://github.com/serg-ai-vn/AI_English_Course . Видимость выбирает владелец; не менять её автоматически. Main содержит принятый код. Историческая первая загрузка и прежние планы не повторяются при каждой задаче.

1. Обновить main, убедиться в чистом статусе и не потерять чужие незакоммиченные изменения. Для одной связной задачи создать короткую ветку от main; назвать по задаче. Два агента не пишут параллельно в один checkout.
2. Воспроизвести проблему, прочитать минимальный контекст по CONTEXT_MAP, выполнить Impact Check. Изменить затронутые слои; не менять методику молча.
3. Проверить npm ci/build/check/test, при изменении пользовательского пути — npm run test:ui. npm run smoke:isolated использует временные данные и собственный сервер. Дополнительные проверки соответствуют риску задачи; не трогать прогресс владельца.
4. Проверить staged diff/список файлов. Не коммитить .env, runtime platform/data, generated, dist, backup, реальные доступы. Ignore не удаляет ранее отслеживаемые файлы: при необходимости снять с индекса, сохранив диск.
5. Push рабочей ветки → один draft Pull Request в main. Описать проблему/результат, проверки и оставшиеся NOT_RUN. Независимый проверяющий повторяет приёмку точного SHA в собственном clone. Исправления по замечаниям идут в ту же ещё не слитую ветку. Ждать зелёный CI.
6. После независимой приёмки сделать PR ready, merge и проверить результат в main. Поставить отдельный tag принятой версии при выпуске; push именно этого tag. Удалить только слитую рабочую ветку на GitHub и локально, обновить main. PR/коммиты/история остаются. Новая ошибка после merge — новая ветка и новый PR.

Существующая arena/0f062cc8-ai-english-course была веткой с двумя отчётами, не второй копией проекта. Она используется для одной итерации проверки и исправлений этих выводов. После принятия объединяется и удаляется; оба отчёта остаются в истории main.

План отката: обычно revert конкретного merge через новую ветку/PR либо развёртывание прежнего проверенного tag/образа. Не делать force push/reset общей main. Код в Git и рабочие данные — разные вещи: возврат кода не восстанавливает JSON/изображения, нужен совместимый snapshot по DEPLOY_RUNBOOK. Merge не развёртывает приложение на сервере автоматически.
